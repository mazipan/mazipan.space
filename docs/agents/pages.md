# Page notes

What is special about individual pages and the data behind them. Check here before changing them.

- **Home:** a pinboard "Right now" with sticky notes built in `src/pages/index.astro` from real data (`PROFILE`, `now.ts`, newest post and slides). The "Based in" note shows `PROFILE.LOCATION` and `PROFILE.TIMEZONE`; a small `time-difference` custom element compares the visitor's browser clock with `PROFILE.TIMEZONE_OFFSET_MINUTES` ("3 hours ahead of you."; nothing is sent anywhere, hidden without JS). The board grid is 2 / 3 / 5 columns for five notes: change it if the note count changes, so no note is left alone on a row. The hero photo is a polaroid of the owner (the old blob avatar is gone).
- **Post page ("the open book"):** `src/layouts/Post.astro`, `src/pages/blog/[slug].astro`, styles in `src/styles/components/post.css`. A cover with a stitched spine (`.post-cover`, color from `getCardTone(category)`, set with `data-tone`; title and description use the key text token of that color), the hero image as a taped print on the cover (`.post-cover-art`), a paper slip along the cover's bottom edge with the meta and tags (`.post-slip`, normal sheet colors), then a 3-column reading area (`.post-grid`: chapter index = `ToC` on the left, the page on `.post-detail`, a rail of share keys on the right on desktop). The page is a stack of page edges (box-shadow layers) with a binding shade inside its left edge; every `content-wrapper > h2` gets a numbered key from a CSS counter (the counter text is hidden from screen readers with `content: ... / ''`), the first paragraph gets a drop cap when the post starts with text, blockquotes are sticky notes (their links use the note text color, a theme link color fails contrast there), `hr` is a dotted stitch line. The end of the post has `PostColophon` (author note), `PostNav` (older/newer), a share row on small screens (the desktop rail is hidden below 1024px) and comments. Layout slots: `hero-text`, `hero-image` (only passed when the post has a hero), `hero-meta`, `bottom-line`, `toc`, `rail`, `content`, `after-content`, `more-posts`. On wide screens (1280px and up) the grid is `1fr / 40.5rem / 1fr`: the chapter index sits on the left edge and the share rail on the right edge, in line with the header and the cover, and the page stays centered; from 1024 to 1279px it is `220px / page / 56px` centered. Share keys are exactly 48 x 48 (`flex: none`, or a flex column squeezes them into ovals). The grid column on phones must be `minmax(0, 1fr)` or a wide code block widens the whole page. Share styles are unlayered, so the rail needs `!important` to override them.
- **Selected projects** on the home page come from `featured: true` in project frontmatter (`getSelectedProjects` in `src/modules/project.ts`).
- **Friends page:** data in `src/constants/friends.ts` (blog, owner, platform, avatar). Interaction is progressive: cards are in the HTML, `friend-list` adds search, filter, sort and shuffle. Avatars always have the initials fallback.
- **Breadcrumbs:** every `Page` layout page has them; put `breadcrumbs: false` in the frontmatter to hide them (the 404 page does).
- **404:** `NotFoundArt.astro` is a 12 second loop: a ginger pixel-art cat hooks the 0 key and lifts it out of its slot (arm up, key floats), finds a dark pixel cat asleep in the slot ("!" and Zs appear), then puts the key back. The cats are crisp `<path>` pixels in fixed colors; the keys and the "!" and Zs use palette tokens (`var(--th-key-edge)`) so they show in dark mode. Motion is CSS keyframes inside `@media (prefers-reduced-motion: no-preference)`; with reduced motion the picture is one still frame (key out, cats and Zs visible). The cat sits close to the key and the arm is short (about 6 cells visible, in proportion to its 11-cell body); the key slides 12px toward the cat when it is lifted so the paw can reach it, and the paw rests on the key's top-right corner when the key is in the slot. If you move the cat, recompute the arm pivot and length so the paw still touches the key in both poses. To change a cat, redraw its small sprite grid (one letter per color) and regenerate the path data (the grids are not kept in the repo). The 404 has no breadcrumbs (`breadcrumbs: false`). Cats are part of the site's personality; more cats are welcome in empty states.
- **Resume order:** `src/constants/career.ts` is newest first; `resume.astro` shows stops oldest first and roles inside one company oldest first too. The card tab reads `Joined <year>` (never 'Exit', it reads like leaving).
- **Resume road:** the dashed center line must be a short tile with `repeat-y` (a single road-high tile ends halfway when scroll shifts it); on phones the road is at `left: 0` on the 48px grid column and the lamp sits on its right edge, so the connector meets it. Do not add a role count to the intro badges. The brown connector is the lamp's own `::after` (not the card's), so they cannot drift apart, and the lamp lifts with the card when a stop is reached (`.stop[data-reached]`), so keep both transforms equal; the lamp's `top` (45px) is tied to the stop padding and card border, so re-measure from screenshots if you touch those.
- **About:** has a "Where I've worked" card that links to `ROUTES.RESUME`; keep the resume reachable from About and the footer.
- **Location and time zone:** `PROFILE.LOCATION` and `PROFILE.TIMEZONE` feed the home 'Based in' note; the footer deploy time is set in `package.json` as Jakarta time with `GMT+7`. If the owner moves, change both, and `PROFILE.TIMEZONE_OFFSET_MINUTES` too (the home note compares the visitor's browser clock with it).
- **Version:** the footer's `v…` comes from `package.json` `version` through `APP_VERSION` (now 3.0.0), so bump it there only.
- **Footer:** `Footer.astro` = raised `.footer-deck` (brand + link groups with `.footer-label` plates) over a recessed `.footer-plate` (small print + back-to-top key). New footer links go into the matching `.footer-links` list.
